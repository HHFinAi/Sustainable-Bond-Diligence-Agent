# GEO / search and generative-discovery implementation

The user's GEO/SGO objective is implemented as clear search and generative-discovery documentation, not as an alleged universal SGO standard or hidden ranking trick. The positioning is visible and domain-specific: institutional-quality buy-side research with a tradable-decision focus and a traceable, auditable workflow.

## Included
An answer-first README defines the entity, audience, problems solved and limits. Descriptive section headings, separate domain prompts, semantic keywords, workflow diagrams and linked sample outputs make the implementation inspectable. FAQ answers explain institutional quality, tradability, evidence and execution boundaries. `CITATION.cff` identifies HHFinAi and the software version. `repository-metadata.json` supplies a concise About description and relevant topics for manual publication. `llms.txt` is optional navigation for readers/agents; it is not required by Google and no crawler support is claimed. `docs/index.html` provides a text-first optional landing page with JSON-LD matching the visible software description; it is not deployed automatically.

Do not keyword-stuff, invent testimonials, claim client adoption, hide caveats, forge third-party certifications or present synthetic examples as real investment performance. Do not claim that a README badge, schema or llms.txt guarantees inclusion in an AI answer. Before publishing, ensure the actual repository URLs and metadata match the public state, respect private visibility and review source licences. Set canonical/hosting URLs only after the site is live. The packages do not enable GitHub Pages or change repository settings.
