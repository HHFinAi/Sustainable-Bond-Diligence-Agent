# Evidence lineage and local audit workflow

A run freezes the request, route, role instructions, standards metadata, operating contract and runtime file hashes. Each submission carries the run ID, input digest and expected revision. Structured claims reference evidence; numeric claims also bind to source metrics. Calculations carry arguments, units, provenance and reproducible outputs. An event hash chain and state digest detect accidental changes. A review binds to the current packet digest.

When upstream work changes, the runtime archives that output and its submitted descendants, clears the review and requires those stages again. Do not amend source evidence inside a run; start a new run with the new evidence set and explain the supersession. Source availability must be on or before the research as-of date. Retrieval can occur later, so record restatements and historical document availability carefully; the engine cannot prove a page existed in its current form at an earlier date.

`export` writes the Markdown packet, complete JSON state, evidence CSV and claims CSV to a new directory. The JSON includes the full calculation lineage and event/review history. CSV text is guarded against common spreadsheet-formula prefixes. Exports do not contain the bytes of linked source documents unless separately, lawfully archived by the user.

**Important limits:** source review flags and human identities are declared, not authenticated. The runtime cannot verify prose against cited evidence. Hashes provide reproducibility and accidental-change detection, not protection against an administrator rewriting both data and hashes. No digital signatures, WORM storage, identity provider, access-control server, regulated retention guarantee or source-licence clearance is included. Local single-writer locking has no automated stale-lock recovery. Back up private runs and adopt institutional identity, access, retention and independent review controls before production use.
